摘要

2026-10-20，PHP 安全团队发出预告：将在 2026-10-21 14:00 UTC（北京时间 22:00） 发布安全版本，修复两个 CVSS v4.0 评分均为 9.2 的严重漏洞，并提醒所有用户提前准备（t/1250659↗ 转贴的官方预告）。V2EX 上流传的服务商预警把它称为 PHP2Shell，描述为可直接拿到服务器 Shell 的远程代码执行漏洞，影响 PHP 5.4 及以上，且官方只为 8.2～8.5 发补丁（t/1250646↗，转贴内容，未核实）。社区的担心集中在两点：一是补丁一发布，攻击者就能通过对比补丁推出利用方法，留给运维的窗口可能只有十几分钟；二是大量 PHP 7 甚至 5 的老系统没人维护、升级困难。实际做法是：能升级的连夜升级（回复称 8.5.12 已发布，Ubuntu、Docker 官方镜像随后跟进），升级不了的先改 php.ini 关闭 session 上传进度、加 WAF 规则，或者干脆在 Nginx 返回 503、关站等补丁。

2026-10-23 补充（与待裁定问题 Q-0027 相关）：宝塔面板官方账号发帖称“因为官方仅提供了 7.4 ，8.0 ，8.1 版本的修复补丁”t/1250832↗，并称自己“参考 PHP 7.4 的修复补丁，逐行比对并回移适配到了更早的版本”t/1250832↗（t/1250832↗）。这与“8.1 及以下没有官方补丁”的早期说法相左；宝塔为第三方，说法未经 php.net 核实，结论待维护人裁定。

关键事实与数据

  • 官方预告：两个漏洞均为 CVSS v4.0 9.2，发布时间 2026-10-21 14:00 UTC（t/1250659↗，转贴自 php.net）。
  • 转贴公告给出的编号为 CVE-2026-109618、CVE-2026-109619，受影响版本“PHP 5.4 及以上”，补丁只覆盖 8.2～8.5（t/1250646↗）。这些来自服务商通知，不是 PHP 官方原文，本库未核实。
  • 回复提到的修复版本：8.5.12（t/1250646 #64↗）；有人在升级前是 8.5.9（t/1250646 #37↗）。
  • 补丁覆盖面有矛盾说法：“8.2 以下不给补丁”（t/1250646 #91↗），但也有人称 8.0 有修复（t/1250646 #76↗）、php-src 有 7.4 修复分支（t/1250646 #71↗）、某面板称 7.4 补丁还在测试（t/1250646 #96↗）。
  • 帖内提到的自检工具与 PoC 链接（t/1250646 #100 ❤1↗、t/1250646 #42↗、t/1250646 #16↗）来源不明，本库不建议直接运行。
  • 宝塔给出的 7.x 回移修复版本号：“PHP 7.0 → 7.0.34 PHP 7.1 → 7.1.34 PHP 7.2 → 7.2.35 PHP 7.3 → 7.3.34”t/1250832↗；7.4 及以上可在面板软件商店更新（t/1250832↗，厂商自述）。

实用建议 / 检查清单

以下按回复整理，适用于手上有 PHP 服务的人：

  • 先盘点：列出所有 PHP 服务和版本，包括被遗忘的博客、面板、内部系统（t/1250646 #3↗、t/1250646 #53↗）。
  • 能升级就升级：用发行版或官方镜像的安全更新，升级后重启 PHP-FPM 等服务（t/1250646↗、t/1250646 #74↗、t/1250646 #90↗）。
  • 升级不了先降暴露面：Nginx 返回 503 或暂时下线（t/1250646 #15↗、t/1250646 #27↗），关闭不必要的公网访问（t/1250646 #82↗），前面加 WAF 规则（t/1250659 #7↗）。
  • php.ini 临时缓解：社区流传关闭 session.upload_progress.enabled、开启 session.use_strict_mode 等（t/1250646 #57↗），来源注明“非可信”，只能当缓解，不能代替补丁。
  • 编译升级留意资源：小内存 VPS 现场编译可能死机或触发告警（t/1250646 #81↗、t/1250646 #84↗）。
  • 不要随手跑来路不明的 PoC/检查脚本：帖内链接无法核实来源。
  • 长期：长期跑在已停止支持版本上的系统，要排进迁移计划（t/1250646 #97↗、t/1250753↗）。
  • 用面板的先看面板通告：宝塔用户按其通报升级；7.0～7.3 为面板方自行回移的补丁，不是 PHP 官方发布，仍建议尽快迁到仍在维护的版本（t/1250832↗）。
