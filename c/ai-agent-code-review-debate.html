摘要

2026-11-02 有人贴出 Claude Code 写的 pandas 代码，说高效简洁但很难看懂，问到底审不审。最高赞回复是一句“能过鸭子测试它就是鸭子”，代表“只看结果”的一派：AI 一天能产出上万行，人审不过来，应改为测试行为是否符合预期、做好安全边界和回滚。另一派强调代码上线出了问题要问责，AI 会偷偷埋坑、某个指标突然算错，AI 互审流程也模糊，人工审核不可替代。折中做法较多：新项目要先用 skill 约束代码风格和架构，之后只看改动了哪些文件；让 AI 换一种不那么优雅但看得懂的写法；按是不是一次性项目、是否涉及金融数学等必须精确的领域决定审核力度。
